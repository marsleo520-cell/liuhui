# PRD：生产订单接口日志查看

## 0. 文档元信息

## 1. 问题与证据

- 用户与任务：查看生产订单的人。岗位名称未知。任务是核对这一张订单何时被 SAP、MES 一类接口同步过。
- 当前障碍：用户说明现有生产订单操作界面看不到接口同步记录，无法从订单上回答接口何时同步了它。
- 代码事实：仓库没有正式的生产订单页面、日志管理页面、SAP 接口、MES 接口或数据对象。原型只模拟筛选和 traceId 点击。
- 用户确认：入口是「更多操作」中的「查看接口日志」。现有界面名称是「日志管理」。查询时把计划号放进「请求体」，不是一个叫「订单号」的字段。开始时间、结束时间必填。列表有操作 IP 地址、操作时间、消耗时间、操作 url、请求状态、模块、具体操作、目标 url、traceId、异常信息，以及「查看」。详情有模块、具体操作、URL、IP、traceId、异常信息、请求头、请求体、响应体，以及 JSON 预览。traceId 可点击并查看后台代码执行过程。
- 不解决的代价：同步发生后，查看的人无法在这张订单上指出对应的接口记录和时间。由此造成的业务损失未知。

## 2. 目标与非目标

### 目标

1. 从当前这张生产订单打开日志管理后，只看到请求体包含该计划号、且落在所选时间内的接口记录。
2. 每条记录能看到操作时间、模块、具体操作、请求状态和 traceId。
3. 点击列表或详情中的 traceId，能进入这一条调用的执行记录。

### 非目标

1. 不展示谁在界面上更新了生产订单。人的更新见《生产订单操作日志查看》。
2. 不在这个界面触发、重试或停止同步。
3. 不修改 SAP、MES 的接口映射、账号和报文配置。
4. 不在本文规定执行记录的日志行和服务名。见《生产订单执行记录查看》。
5. 不把结果强行收成「SAP 一行、MES 一行」。一条接口调用就是一行。
6. 不重做日志管理里与本订单筛选无关的模块。
7. 不做导出和统计。

### 后续

1. 若确认需要，再提供手动重新同步。那是另一个任务。
2. 若确认需要，再把「模块」或「具体操作」固定映射到 SAP 或 MES 的枚举。

## 4. 方案说明

- 方案：沿用现有日志管理。从订单进入时，把该订单计划号填入请求体，开始时间和结束时间使用用户可改的必填值。搜索后列出接口记录。点击「查看」打开详情。点击列表或详情中的 traceId，进入执行记录。
- 沿用的现有模式：用户给出的日志管理筛选项和列。开始时间、结束时间、模块、操作、发送方 URL、请求体、响应体、traceId、异常信息；列表列与详情字段见用户确认。本仓库没有读到该页的正式代码。
- 新增模式及理由：从生产订单「更多操作」带入计划号。现有日志管理本身不知道用户正在看哪一张订单，所以需要把计划号填进请求体。
- 被放弃的做法及理由：SAP 与 MES 各固定一行。用户给出的日志管理是多行接口记录，SAP 与 MES 体现在模块和具体操作上。新增「订单号」查询字段。用户明确用请求体承载计划号。在本页直接铺开后台执行日志。执行记录另文规定，避免两个日志各做一套。

## 5. 信息架构与流程

### 入口与出口

入口：生产订单列表中，目标订单行的「更多操作」→「查看接口日志」。打开的页面标题为「日志管理」。

出口：返回进入前的生产订单列表。从 traceId 进入执行记录后，返回回到日志管理，并保留刚才的筛选。关闭详情回到日志列表，不离开日志管理。

### 主路径

1. 用户在生产订单列表找到目标订单。
2. 用户点击该行「更多操作」，再点击「查看接口日志」。
3. 系统打开日志管理，请求体中已填入该订单计划号。开始时间、结束时间有可改的值，且两者都必填。
4. 用户点击搜索。系统只展示同时满足这些条件的记录：操作时间在开始与结束之内，请求体包含该计划号。时间近的在前。
5. 用户查看操作时间、消耗时间、操作 url、请求状态、模块、具体操作、目标 url、traceId、异常信息。
6. 用户点击「查看」。系统打开详情，展示模块、具体操作、URL、IP、traceId、异常信息、请求头、请求体、响应体。用户可切换 JSON 预览。
7. 用户点击列表或详情中的 traceId。系统打开《生产订单执行记录查看》，范围只有这一条 traceId。
8. 用户返回日志管理，再返回生产订单列表。

### 分支路径

1. 开始时间或结束时间为空时，系统不发起查询，并说明缺的是哪一个时间。结束时间早于开始时间时，系统不查询，并说明结束时间要晚于开始时间。
2. 查询结果为空时，系统展示「没有符合条件的接口日志」，筛选条件保留。
3. 正在获取时，系统展示「正在加载接口日志」。加载必须能结束，并进入成功或失败。
4. 获取失败时，系统展示「接口日志没有加载出来」。用户重试且成功后，系统展示记录，并显示「已重新获取」。
5. 用户没有查看权限时，系统不展示记录、请求体和 traceId，只说明不能查看，并允许返回订单列表。
6. 时间为 00:00:00 或 23:59:59，或 url、异常信息很长时，操作时间、traceId 和这些长文本仍然完整可见。
7. 用户点击重置后，系统清空筛选，不保留从订单带入的计划号，直到用户再次从订单进入。

## 6. 功能需求

按 P0 / P1 排列。P0 是没有它任务就失败的项。

### P0-1 从当前订单进入日志管理

- 用户故事：作为查看生产订单的人，我要从当前订单打开接口日志，以便只核对本张订单。
- 规则：当用户点击「查看接口日志」时，系统打开日志管理，并把该订单计划号填入请求体。
- 反馈：成功时看到筛选区，请求体里是该计划号。失败时看到失败说明。
- 数据：读取计划号。计划号与请求体字段的正式接口名待确认。

### P0-2 按时间和请求体查询

- 用户故事：作为查看生产订单的人，我要按时间和计划号查出接口记录，以便知道何时发生过同步。
- 规则：当开始时间和结束时间都已填写，且结束时间晚于开始时间时，系统展示该时间范围内、请求体包含当前计划号的记录。每条显示操作 IP 地址、操作时间、消耗时间、操作 url、请求状态、模块、具体操作、目标 url、traceId、异常信息。操作时间近的在前。
- 反馈：成功时看到记录。无记录时走空状态。时间不合法时看到对应说明，且不展示上一次的结果冒充本次结果。
- 数据：读取接口日志。哪些模块或具体操作代表 SAP，哪些代表 MES，待确认。

### P0-3 查看单条详情

- 用户故事：作为查看生产订单的人，我要打开一条接口日志的详情，以便核对请求和响应。
- 规则：当用户点击「查看」时，系统打开详情，展示模块、具体操作、URL、IP、traceId、异常信息、请求头、请求体、响应体。当用户点击 JSON 预览时，系统展示请求体和响应体的 JSON 文本。当用户取消或按 Esc 时，系统关闭详情并回到原来的列表。
- 反馈：详情与该行是同一条记录。关闭后列表筛选仍在。
- 数据：读取该条日志的请求头、请求体、响应体。是否包含凭证待确认。

### P0-4 展示并可点击 traceId

- 用户故事：作为查看生产订单的人，我要点开这条接口日志的 traceId，以便查看这次调用的后台执行过程。
- 规则：当列表或详情中有 traceId 时，系统显示它，并且可以点击。当用户点击时，系统打开《生产订单执行记录查看》，并只传入这一条 traceId。详情若开着，点击后关闭详情。
- 反馈：成功时进入执行记录。traceId 为空时，该位置显示「待确认」，且不能点开。
- 数据：读取 traceId。与操作日志是否同一套编号待确认。

### P0-5 只读

- 用户故事：作为查看生产订单的人，我要在接口日志里只查看，以便不会在核对时发起新的同步。
- 规则：当用户位于日志管理或详情时，系统不提供重新同步、停止同步、保存或编辑订单。
- 反馈：界面上没有这些操作。打开日志不改变订单，也不向 SAP 或 MES 发送同步请求。
- 数据：不写生产订单，不写外部系统。

### P0-6 返回

- 用户故事：作为查看生产订单的人，我要返回原来的订单列表，以便继续处理这张订单。
- 规则：当用户在日志管理点击返回时，系统回到进入前的生产订单列表。当用户从执行记录返回时，系统回到日志管理，并保留进入执行记录前的筛选。
- 反馈：回到的页面与点击的返回一致。
- 数据：不新增读写。

### P0-7 空、加载、失败、无权限与边界

- 用户故事：作为查看生产订单的人，我要在没有数据、加载、失败、没权限和极端内容时知道真实状态，以便不把异常当成「没有同步过」。
- 规则：当查询结果为空时，系统显示「没有符合条件的接口日志」。当加载中时，系统显示「正在加载接口日志」，并允许结束加载。当加载失败时，系统显示「接口日志没有加载出来」，并允许重试；重试成功后展示记录，并显示「已重新获取」。当无权限时，系统不展示记录。当时间为 00:00:00 或 23:59:59，或 url、异常信息很长时，系统仍完整展示操作时间、traceId 和长文本。
- 反馈：见规则中的文案。
- 数据：权限判定来源待确认。失败原因码待确认。

P1：无。重新同步和 SAP/MES 枚举映射放在「后续」。

## 8. 数据与业务规则

- 对象：生产订单；接口日志。存储结构未知。
- 字段与校验：筛选字段为开始时间、结束时间、模块、操作、发送方 URL、请求体、响应体、traceId、异常信息。开始时间和结束时间必填，结束时间必须晚于开始时间。从订单进入时请求体预填计划号。列表和详情字段见用户确认。本版不新增「订单号」字段。请求状态沿用日志原文，不把未知状态改写成成功或失败。

- 排序、去重、并发、撤销：按操作时间从新到旧。同一秒的多条记录都保留。本界面不提供重新同步，也不提供撤销。
