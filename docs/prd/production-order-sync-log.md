# PRD：生产订单接口同步日志查看

## 0. 文档元信息

- 状态：待确认
- 日期：2026-10-09
- 相关代码：尚未定位
- 一句话：查看生产订单的人在某一张生产订单上打开同步日志，看到 SAP 和 MES 在哪一分钟同步了这张订单，从而核对接口是否同步过。

## 1. 问题与证据

- 用户与任务：查看生产订单的人。岗位名称未知。任务是核对这一张订单何时被 SAP 同步、何时被 MES 同步。
- 当前障碍：用户说明现有生产订单操作界面没有接口同步日志查看界面，无法从订单上回答「几点几分 SAP 和 MES 同步了它」。
- 代码事实：已读 `/workspace/README.md`，全文是标题「liuhui」和正文「anything」。仓库中没有生产订单页面、同步日志页面、SAP 接口、MES 接口或数据对象。
- 用户确认：已有生产订单操作界面；需要接口同步日志查看界面；日志要能表达几点几分 SAP 和 MES 同步了生产订单。
- 不解决的代价：同步发生后，查看的人无法在界面上指出 SAP 或 MES 的同步时间。由此造成的业务损失未知。

## 2. 目标与非目标

### 目标

1. 从当前这张生产订单打开同步日志后，能看到 SAP 的同步时间和 MES 的同步时间，时间精确到分钟。

### 非目标

1. 不展示谁更新了生产订单。人的更新记录见独立文档《生产订单操作日志查看》。
2. 不在这个界面触发、重试或停止同步。
3. 不修改 SAP、MES 的接口映射、账号和报文配置。
4. 不展示 SAP、MES 以外的系统。
5. 不重做生产订单操作界面里与同步日志无关的操作。
6. 不做导出、统计和跨订单检索。

### 后续

1. 若确认需要，再展示同步方向、成功或失败、报文摘要。
2. 若确认需要，再提供手动重新同步。那是另一个任务，不放进本次查看范围。

## 3. 用户与场景

| 角色 | 前置条件 | 触发 | 主任务 | 成功结果 |
| --- | --- | --- | --- | --- |
| 查看生产订单的人 | 正在看某一张生产订单。岗位名称未知。 | 在该订单的操作界面打开同步日志 | 核对 SAP 与 MES 何时同步了这张订单 | 看到两个系统各自的同步时间，精确到分钟，且不能在这里发起同步 |

## 4. 方案说明

- 方案：在当前生产订单上增加一个只读的接口同步日志查看界面。SAP 一行，MES 一行。每行展示系统名称和到分钟的同步时间。同步方向、结果、报文显示「待确认」。
- 沿用的现有模式：无。仓库里没有读到可沿用的页面、组件、路由或文案。
- 新增模式及理由：订单内的只读同步列表。仓库没有现成列表可以沿用，用户要分别看到 SAP 和 MES 的同步时间。
- 被放弃的做法及理由：和操作日志共用一张表。人和系统同步不是同一件事。在本界面放「重新同步」。用户这次要的是查看，不是发起同步。把两个系统写成一行且不区分时间。这样无法分别回答 SAP 和 MES 的同步时间。

## 5. 信息架构与流程

### 入口与出口

入口：当前生产订单操作界面中的「查看同步日志」。该界面在本仓库中尚未定位，按钮放在哪一个区域待确认。

出口：返回进入前的那张生产订单操作界面。

### 主路径

1. 用户打开某一张生产订单的操作界面。
2. 用户点击「查看同步日志」。
3. 系统展示这张订单的同步记录。SAP 与 MES 各自成行，每行有系统名称和到分钟的同步时间，时间近的在前。
4. 用户点击一条记录。系统展示系统名称和同步时间；同步方向、同步结果、报文显示「待确认」。
5. 用户返回列表，再返回生产订单操作界面。

### 分支路径

1. 没有任何同步记录时，系统展示空状态，不用空白表格假装同步过。
2. 正在获取时，系统展示加载状态。加载必须能结束，并进入成功或失败。
3. 获取失败时，系统说明失败。用户重试且成功后，系统展示记录，并标明这是一次新的获取。
4. 用户没有查看权限时，系统不展示任何系统和时间，只说明无权限，并允许返回订单。
5. 时间为 00:00、23:59，或说明文字很长时，系统名称和同步时间仍然完整可见。

## 6. 功能需求

按 P0 / P1 排列。P0 是没有它任务就失败的项。

### P0-1 从当前订单进入同步日志

- 用户故事：作为查看生产订单的人，我要从当前订单打开同步日志，以便只核对本张订单。
- 规则：当用户在某一张生产订单上打开同步日志时，系统只展示这张订单的 SAP 与 MES 同步记录。
- 反馈：成功时看到同步列表或空状态。失败时看到失败说明。
- 数据：读取生产订单标识和同步日志。订单标识的字段名待确认。

### P0-2 查看 SAP 与 MES 的同步时间

- 用户故事：作为查看生产订单的人，我要看到 SAP 和 MES 几点几分同步了订单，以便核对接口是否同步过。
- 规则：当存在同步记录时，系统按同步时间从新到旧展示。每条显示系统名称和同步时间（到分钟）。系统名称只使用 SAP 或 MES。
- 反馈：成功时两个系统的时间都可见。没有记录时走空状态，不显示编造的同步时间。
- 数据：系统名称、同步时间。同步方向、同步结果、报文待确认。

### P0-3 只读

- 用户故事：作为查看生产订单的人，我要在同步日志里只查看，以便不会在核对时发起新的同步。
- 规则：当用户位于同步日志时，系统不提供重新同步、停止同步、保存或编辑订单。
- 反馈：界面上没有这些操作。打开日志不改变订单，也不向 SAP 或 MES 发送同步请求。
- 数据：不写生产订单，不写外部系统。

### P0-4 返回

- 用户故事：作为查看生产订单的人，我要返回原来的订单，以便继续处理这张订单。
- 规则：当用户在详情点击返回时，系统回到同步列表。当用户在列表点击返回时，系统回到进入前的那张生产订单操作界面。
- 反馈：先看到列表，再看到原来的订单。
- 数据：不新增读写。

### P0-5 空、加载、失败、无权限与边界

- 用户故事：作为查看生产订单的人，我要在没有数据、加载、失败、没权限和极端时间时知道真实状态，以便不把异常当成「没有同步过」。
- 规则：当日志为空时，系统显示「这张生产订单还没有同步日志」。当加载中时，系统显示「正在加载同步日志」，并允许结束加载。当加载失败时，系统显示「同步日志没有加载出来」，并允许重试；重试成功后展示记录，并显示「已重新获取」。当无权限时，系统不展示记录。当时间为 00:00、23:59，或说明超过一行时，系统仍完整展示系统名称和同步时间。
- 反馈：见规则中的文案。
- 数据：权限判定来源待确认。失败原因码待确认。

P1：无。同步方向、结果、报文、手动重新同步、筛选和导出尚未被确认，放在「后续」，不进入本次范围。

## 7. 界面状态

| 状态 | 出现条件 | 用户看到 | 用户可做 |
| --- | --- | --- | --- |
| 空 | 当前订单没有任何同步记录 | 「这张生产订单还没有同步日志」，没有数据行 | 返回订单 |
| 加载 | 正在获取日志 | 「正在加载同步日志」，没有数据行 | 结束加载。结束后进入成功或失败 |
| 成功 | 获取到 SAP 或 MES 的同步记录 | 系统名称、到分钟的同步时间 | 打开详情、返回订单 |
| 失败 | 获取日志失败 | 「同步日志没有加载出来」 | 重试、返回订单 |
| 无权限 | 当前用户不能查看该订单的同步日志 | 「当前账号不能查看同步日志」，没有记录内容 | 返回订单 |
| 边界 | 时间为当天 00:00 或 23:59，或说明文字很长 | 系统名称和同步时间都完整可见 | 打开详情、返回 |

## 8. 数据与业务规则

- 对象：生产订单；生产订单接口同步日志。存储结构未知。
- 字段与校验：展示系统名称、同步时间。系统名称只允许 SAP 或 MES。同步时间展示到分钟。同步方向、同步结果、报文待确认，本版不把「待确认」写成成功或失败。订单标识字段名待确认。
- 权限：无查看权限时不展示记录。权限点名称未知。
- 排序、去重、并发、撤销：按同步时间从新到旧。同一分钟的 SAP 与 MES 都保留。本界面不处理并发写入。本界面不提供撤销，也不提供重新同步。
